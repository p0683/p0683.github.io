QQ流量分析：新版QQ图片传输是明文吗？——基于Wireshark的抓包实验

课程作业：QQ 流量分析（PC-PC 端、PC-手机端）
本文实验覆盖 PC-手机 场景（手机 QQ ↔ 电脑 QQ 互发图片）

一、实验要回答的四个问题

  1. QQ 传输用 UDP 还是 TCP？
  2. 传输内容是加密还是明文？
  3. 如果是明文传输，能否利用文件头特征码从流量中恢复原文件？在线传输方式下文件数据长什么样？
  4. 图片在两端之间是直连（P2P）还是经服务器中转？

二、实验环境

项目 说明
抓包工具 Wireshark 4.6.9
QQ 版本 新版 QQ（NT 架构，Windows 9.x / 手机版）
网络拓扑 电脑开启移动热点，手机连热点，Wireshark 抓取热点虚拟网卡（”本地连接* 10”），手机全部流量经电脑
测试文件 手机相册 PNG 图片一张，627 KB，发送时勾选”原图”
操作 手机 QQ 向电脑 QQ 发送图片，22:10 左右，电脑端确认接收完成
手机 IP 192.168.137.x（博客中已打码）

抓包方法要点：电脑开热点让手机流量必经抓包网卡；发送图片后停止抓包并保存 pcapng。

三、分析过程

3.1 协议统计：只有 TCP，没有 UDP

菜单”统计 → 协议分级（Protocol Hierarchy）”显示，本次捕获的 QQ 相关流量全部是 TCP，其上层全部是 TLS，没有任何 UDP 流量。

结论 1：新版 QQ 在本场景下仅使用 TCP，不使用 UDP。

3.2 定位图片传输流

发送图片的瞬间，捕获中出现一条约 881 KB 的 TCP 流（图片本身 627 KB，密文+协议开销后略大），用显示过滤器 tcp.stream eq 4 单独查看：

图中可见：

  • 对端 IP 为腾讯服务器（14.22.20.217），不是手机与电脑之间的直连；
  • 端口为 443（标准 HTTPS 端口）；
  • 协议列显示 TLSv1.2；
  • 大量 1414 字节的连续数据包正是图片数据在传输；
  • Info 列显示 “Ignored Unknown Record“——Wireshark 无法解析 TLS 记录内容，这正是密文的直接表现。

结论 2：图片传输走 服务器中转，且封装在 TLS 1.2 加密通道内。

3.3 加密还是明文：定量判定

对这条流执行”追踪 TCP 流”并导出为原始二进制文件（881,740 字节），做以下检测：

（1）文件头特征码检索（明文恢复的前提）

特征码 含义 结果
89 50 4E 47 (‰PNG) PNG 文件头 未命中
FF D8 FF JPG 文件头 未命中
JFIF / Exif JPG 内部标识 未命中
%PDF、PK\x03\x04、GIF8、http:// 等 其他常见文件/协议头 全部未命中

全文检索零命中——流中不存在任何明文文件头。

（2）香农熵检测

  • 计算结果：7.9998 / 8.0
  • 明文图片（PNG/JPG）熵一般在 7.2~7.9，且文件内部存在重复结构；
  • 本流熵趋近理论最大值且字节分布近乎均匀（每种字节出现 3333~3699 次）——典型的加密数据特征。

（3）TLS 记录结构验证

对全文搜索 TLS 记录头（类型 ∈ {14,15,16,17,18} + 版本 0x03xx + 合法长度），随机数据的期望仅 0.3 个，实际找到 33 个候选；其中从偏移 614528 起有 25 条 17 03 03 类型的应用数据记录严丝合缝地连续贯穿到流结尾。这是标准 TLS 记录层（0x17 = Application Data，0303 = TLS 1.2 记录版本）。

结论 3：图片数据被 TLS 1.2 加密，整条流无明文特征。

3.4 文件恢复尝试

按作业思路尝试”文件头定位 + 截断还原”：

  1. 追踪流 → 显示为”原始数据” → 另存为 test.bin；
  2. 用 HxD 打开检查文件头：开头为 69 ee 22 e7 ...，既不是 89 50 4E 47 也不是 FF D8 FF；
  3. 由于没有合法的明文起始点，无法切割出任何可识别的文件。

结论 4：恢复失败。图片位于 TLS 密文内部，没有会话密钥就无法解密，”文件头特征码还原法”在新版 QQ 上不成立。

四、四问总结

问题 结论
UDP or TCP 仅 TCP（协议分级截图佐证，无 UDP）
加密 or 明文 加密：TLS 1.2，经 443 端口
能否恢复明文文件 不能。文件头特征码 0 命中、熵 7.9998、无 TLS 密钥，图片在密文内
传输方式 服务器中转：图片经腾讯服务器（14.22.20.217:443）在两端的 QQ 之间转发，而非手机↔电脑 P2P 直连

五、讨论

  1. 早年（QQ 2012~2019 时代）的图片传输使用私有协议、部分环节为明文或弱混淆，网络安全课程的经典实验”从 Wireshark 抓包中还原 QQ 图片”正是利用这一点。本次实验证明，新版 QQ（NT 架构）已全面转向标准 TLS，聊天消息与图片均经 443 端口加密传输，历史还原手法全部失效。
  2. 这正回答了作业中”恢复可能为明文传输的文件”这一前提：是否明文取决于传输协议本身。实验设计应”先判定明文/加密，再谈恢复”——判定明文的方法（文件头检索、熵分析）即使最终恢复失败，分析过程本身已构成完整结论。
  3. 实验局限：仅测试了图片的”在线/原图”发送路径。QQ 还存在离线文件、面对面快传（局域网 P2P）等其他传输模式，其协议可能不同，值得后续对比实验（面对面快传预期会出现手机与电脑 IP 之间的大流量直连流）。

六、隐私保护说明

文中已对手机内网 IP 打码（192.168.137.x），未出现 QQ 号、昵称等个人信息；截图均不含聊天记录内容。
